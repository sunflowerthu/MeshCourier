# MeshCourier

Офлайн-мессенджер с отложенной доставкой сообщений на основе BLE mesh-сети и шифрования по российским стандартам ГОСТ.

## О проекте

MeshCourier позволяет обмениваться сообщениями без доступа к интернету и мобильной сети. Устройства обнаруживают друг друга через Bluetooth Low Energy и передают сообщения напрямую, образуя децентрализованную ячеистую сеть. Каждое устройство одновременно является отправителем и ретранслятором — оно перенаправляет чужие сообщения дальше по цепочке.

Если получатель временно недоступен, сообщение сохраняется на промежуточном устройстве и доставляется при первой возможности. Всё содержимое переписки защищено сквозным шифрованием по ГОСТ — промежуточные узлы физически не могут прочитать чужие сообщения.

## Возможности

- **Офлайн-работа** — не требует интернета, Wi-Fi или мобильной сети
- **Mesh-сеть** — автоматическое обнаружение соседних устройств без сопряжения
- **Отложенная доставка** — сообщения сохраняются и доставляются при появлении получателя
- **Сквозное шифрование** — ГОСТ Р 34.10-2012 (подпись, выработка ключа) + ГОСТ Р 34.12-2015 Кузнечик (шифрование)
- **Передача файлов** — изображения и файлы произвольного типа
- **QR-коды** — обмен публичными ключами и идентификаторами узлов

## Архитектура

Проект построен по принципам **Clean Architecture** с разделением на три слоя:

```
presentation/     — слой взаимодейтсвий с пользователем
data/             — слой данных (работа с базой данных, реализации репозиториев, работа с КриптоПро CSP)
domain/           — бизнес-логика, независима от платформы
```

Слой представления использует паттерн **MVVM**: ViewModel хранит состояние экрана, Compose-интерфейс реактивно отображает его через StateFlow.

### BLE-стек

```
BleAdvertiser       — рекламирует присутствие узла в эфире
BleScanner          — сканирует соседние узлы
BleGattServer       — принимает входящие пакеты
BleTransport        — отправляет пакеты с фрагментацией по MTU
PacketAssembler     — собирает фрагменты обратно в пакет
```

### Протокол пакетов

Бинарный формат, минимальный заголовок 40 байт, максимальная полезная нагрузка 32 КБ. Типы пакетов: `MESSAGE`, `ACK`, `HELLO`, `KEY_EXCHANGE`. Фрагментация: пакеты разбиваются на фрагменты по 247 байт.

### Шифрование

```
Подпись:       ГОСТ Р 34.10-2012
Выработка ключа: VKO (ГОСТ Р 34.10-2012)
Шифрование:    ГОСТ Р 34.12-2015 / CTR-ACPKM (Кузнечик), nonce 16 байт
Хэш:           ГОСТ Р 34.11-2012 (256 бит)
Хранилище:     HDIMAGE
```

Формат зашифрованного сообщения:
```
[nonce][зашифровано: [флаг][текст][подпись]]
```

- Поддержка Bluetooth Low Energy
- Камера (для сканирования QR-кодов)
